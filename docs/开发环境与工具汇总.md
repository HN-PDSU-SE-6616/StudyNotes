# 开发环境与工具汇总（Taot 知识库 NoteLog）

> 目的：汇总本项目涉及的全部工具链，含安装、配置与日常用法。命令示例默认在
> 项目根目录 `D:\PythonProject\NoteLog` 执行；Windows PowerShell / CMD 均可。
> 相关文件：`README.md`、`deploy/infra.ps1`、`deploy/monitoring/`、`start.ps1`。

## 1. 运行时与依赖管理

### Python + uv（工程要求 Python 3.12）
- 安装：`irm https://astral.sh/uv/install.ps1 | iex`（或 pip 安装 uv）。
- 配置：`pyproject.toml` 声明依赖；`uv.lock` 冻结版本（`requirements*.txt` 为历史说明）。
- 常用：
  - `uv sync --frozen`：按锁文件安装（无锁则 `uv sync`）；
  - `uv sync --extra ai`：额外安装本地 Embedding（torch/sentence-transformers），一般不需；
  - `uv add <pkg>` / `uv remove <pkg>`：增删依赖并自动更新锁文件；
  - `uv run <cmd>`：在项目虚拟环境内运行命令（uvicorn/alembic/pytest/脚本等）；
  - `uv run python -m py_compile <file...>`：语法校验。
- 说明：虚拟环境目录 `.venv/`（已被 .gitignore 排除）。

### Node.js + npm（要求 Node 18+，当前 v24）
- 安装：https://nodejs.org/ ；前端依赖在 `frontend/package.json`。
- 常用：
  - `cd frontend && npm install`：安装前端依赖；
  - `npm run dev`：Vite 开发服务器（默认 http://127.0.0.1:5173，已配代理到后端 8000）；
  - `npm run build`：产物输出 `frontend/dist`（后端直接托管该静态目录）。

## 2. 一键启动 / 基础设施

### start.ps1 / start.bat（一键启动 & 环境自检）
- 用法：
  - `powershell -ExecutionPolicy Bypass -File start.ps1`（完整启动：自检→infra→uv sync→迁移→四窗口）；
  - `powershell -ExecutionPolicy Bypass -File start.ps1 -CheckOnly` 或 `start.bat check`（仅环境自检）；
  - `start.bat`（等价一键，双击或命令行调用）。
- 行为：预检 uv/node/docker、`.env`（含 CORS JSON 数组格式校验）、端口 5432/6333/6379/6080/8000/5173；
  分别弹出 后端 / Celery Worker / Celery Beat / 前端 四个独立窗口。
- 提示：PowerShell 5.1 对无 BOM UTF-8 中文会乱码，脚本控制台输出已用 ASCII。

### deploy/infra.ps1（独立基础容器，幂等）
- 用法：`powershell -ExecutionPolicy Bypass -File deploy/infra.ps1`（可重复执行）；
  `-OnlyMysql` 只补建 MySQL。容器加 `com.taot.infra=true` 标签、连外部网络 `taot-net`，
  日志驱动 `json-file`（20MB×3 轮换）。
- 端口：PostgreSQL 5432、Redis 6379、Qdrant 6333/6334、MySQL 3306（仅复用）、Embedding 6080。

### Docker
- 工具：Docker Desktop（Windows）。本项目容器均以“独立容器 + 外部网络 taot-net”方式编排。
- 常用：
  - `docker ps` / `docker logs -f <name>` / `docker stats`；
  - `docker compose up -d --build backend worker beat`（应用容器，可选部署方式）；
  - `docker compose -f deploy/monitoring/docker-compose.yml up -d`（监控栈，见 §8）；
  - `docker system df`（磁盘占用）；日志时间清理见 `scripts/cleanup_docker_logs.ps1`。

## 3. 后端框架与服务

### FastAPI + Uvicorn（本地运行后端）
- 配置：`.env`（SECRET_KEY/ALGORITHM/DATABASE_URL/QDRANT_URL/REDIS_URL/EMBEDDING_*/LLM_*/CORS_ORIGINS）。
- 启动：`uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`；
  文档 `/docs`（仅本机），OpenAPI `/openapi.json`。
- 结构：`app/routers/*`（auth/orgs/projects/notes/blocks/files/imports/profile/rag/recommendations/assistant/hotspots/convert）、
  `app/services/*`、`app/core/*`（config/security/permissions/metrics）、`app/tasks/*`（Celery）。

### SQLAlchemy + SQLModel + Alembic
- 数据模型 `app/models/*`（PostgreSQL + JSONB）；迁移 `alembic/versions/*`。
- 常用：`uv run alembic upgrade head` / `uv run alembic revision --autogenerate -m "..."` / `uv run alembic heads`。
- 说明：`DATABASE_URL` 指向独立容器 PostgreSQL（用户 taot/taot，库 taot）。

### Celery + Redis（异步任务）
- Worker：`uv run celery -A app.worker.celery_app worker -Q parse,index -l info -P solo`（Windows 用 `-P solo`）；
- Beat：`uv run celery -A app.worker.celery_app beat -l info`（每日 02:00 刷新推荐）；
- 任务：文件解析（parse）、向量索引（index）、推荐刷新（recommend）；Redis 同时承担会话/热缓存。

## 4. 向量与 Embedding（RAG）

### Qdrant（向量库）
- 独立容器 `qdrant`，Dashboard http://localhost:6333/dashboard；集合 `kb_notes`、`user_profiles`（512 维 Cosine）。
- 维度不一致时启动会告警，按提示执行重建。

### Embedding（bge-small-zh 容器服务，TEI）
- 独立容器映射 `6080:80`；OpenAI 兼容接口（带 key），`.env` 关键项：
  `EMBEDDING_PROVIDER=api`、`EMBEDDING_BASE_URL=http://127.0.0.1:6080/v1`（404 时核对 /v1）、
  `EMBEDDING_MODEL=bge-small-zh`（容器内注册名）、`EMBEDDING_PRESET=bge-small-zh`、`EMBEDDING_DIM=512`。
- 更换模型/维度后重建：`uv run python scripts/rebuild_embeddings.py --reset --reindex`。

### RAG / Agent 服务
- `app/services/rag.py`（检索→上下文→LLM）、`app/services/qdrant_service.py`；
- `app/services/tools.py`（工具注册表：web_search/web_research/get_weather/get_ip/get_system_info/fetch_web_page/search_knowledge_base）；
- `app/services/agent.py`（工具循环 + 会话上下文 + 上下文感知热缓存）、`app/services/agent_flow.py`（计划层）；
- LLM 走 OpenAI 兼容（DeepSeek）：`LLM_API_KEY/LLM_BASE_URL/LLM_MODEL`。

## 5. 前端技术栈（Vue 3 + TS + Tailwind）
- 依赖在 `frontend/package.json`：vue3/pinia/vue-router/axios/marked/dompurify/highlight.js/tailwind/vite。
- 组件划分：`views/*` 页面、`components/*`（layout/notes/assistant/rag/hotspot/common）、`stores/*`（Pinia）、`api/*`（axios）。
- 关键约定：Composition API `<script setup>`；媒体 URL 统一走 `utils/media.ts` 的 `mediaUrl()`（自动附加 access_token）。

## 6. 文件存储（LocalFS）
- 根目录 `storage/`；新文件按 `{owner_id}/{category}/{yyyy}/{mm}/{file_id}{ext}` 落盘
  （category：document/note_image/note_asset/user_avatar/assistant_icon/assistant_bg/assistant_media）；
- 存量文件 storage_key 不变（新老并存）；媒体访问经 `/api/v1/files/...` 鉴权（支持 `?access_token=`）。

## 7. 测试与质量
- `uv run pytest -q`：全量测试（独立测试库 `taot_test` 自动建库+迁移；需基础容器在运行）。
- `uv run pytest tests/test_parser.py -q`：纯解析单测。
- 远程 Embedding 探测（可选）：`$env:RUN_REMOTE_EMBED=1; uv run pytest tests/test_file_media_links.py -q`。
- 前端构建：`cd frontend && npm run build`；语法/编译告警可在 IDE Problems 中查看。

## 8. APM 监控（Prometheus + Grafana，本次新增）
- 依赖：`prometheus-client`（已入 pyproject/uv.lock）；后端内置 `/metrics`。
- 指标（Prometheus 文本格式）：`taot_http_requests_total`（按 method/route/status）、
  `taot_http_request_duration_seconds`（直方图 p95/p99）、`taot_http_inflight_requests`、
  `taot_agent_tool_calls_total`（按 tool/ok）。
- 编排：`deploy/monitoring/docker-compose.yml`（prometheus 9090 + grafana 3000，网络 taot-net）。
- 启动（需 Docker 可拉取镜像，Docker Hub 可达）：
  `docker compose -f deploy/monitoring/docker-compose.yml up -d`
- 抓取：本地后端跑在宿主机 → prometheus.yml 用 `host.docker.internal:8000`；
  若后端跑在容器 `taot-backend`，把 target 改为 `taot-backend:8000`。
- Grafana：http://localhost:3000（admin/admin），已预置数据源与面板
  “Taot 后端监控”（QPS/延迟分位/5xx 占比/并发/工具调用/存活），配置见
  `deploy/monitoring/grafana/provisioning/`。
- 常用查询示例：
  `sum(rate(taot_http_requests_total[5m])) by (status)`、
  `histogram_quantile(0.95, sum(rate(taot_http_request_duration_seconds_bucket[5m])) by (le))`、
  `sum(rate(taot_agent_tool_calls_total{ok="false"}[5m])) by (tool)`。

## 9. Git 协作
- 远端：`git@github.com:HN-PDSU-SE-6616/StudyNotes.git`（master）。
- 误提交“中间/生成文件”的清理方法（当前 master 已审计无 storage/uploads/dist/.env/venv 等被追踪）：
  1. 查看已追踪文件是否包含应忽略项：`git ls-files | findstr <关键字>`；
  2. 移出跟踪但保留本地：`git rm -r --cached <路径>`（例如 `git rm -r --cached frontend/dist storage .env`）；
  3. 确保 `.gitignore` 已覆盖对应路径（见仓库 .gitignore），再 `git add .gitignore && git commit`；
  4. 推送后远端不再包含：`git push origin master`；
  5. 若历史提交中已有大文件/敏感文件且想彻底移除：谨慎使用
     `git filter-repo --path <路径> --invert-paths`（需重写历史并强制推送，团队需同步），
     或用 `git rm --cached` + 新建提交的常规做法保留历史但停止跟踪。
- 工具临时文件规范：一次性诊断脚本命名 `*_space.py` 之类会命中 `.gitignore`；提交前先 `git status` 复核。
